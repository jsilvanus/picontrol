# pitube Integration Contract for picontrol

This document specifies what **`pitube` provides** (endpoints, state, metrics, preview) and what it **expects from `picontrol`** (and `pigateway` acting as the control-plane gateway).

---

## 1. System Context & Routing

`picontrol` runs in the browser and connects to `pigateway` on the LAN. `pitube` is a standalone daemon running alongside `pigateway` (default port: `3105`).

* **Single Ingress Rule:** `picontrol` never calls `pitube` directly over a separate port. `pigateway` proxies all `/api/v1/youtube/*` routes to `pitube`'s `/api/v1/*` routes (or directly forwards them).
* **SSE Event Bus:** `pigateway`'s SSE bus (`GET /api/v1/events?types=youtube`) pushes real-time status updates generated by `pitube` directly to `picontrol`.

```
┌────────────────────────┐                   ┌──────────────┐                 ┌────────────┐
│ picontrol (Browser UI) │──HTTP /api/v1/yt──►│  pigateway   ├──HTTP :3105────►│   pitube   │
│                        │◄──SSE /events─────│  (port 3100) │◄──PUT /status───│ (daemon)   │
└────────────────────────┘                   └──────────────┘                 └─────┬──────┘
                                                                                    │
                                                                   YouTube Data API │
                                                                   & Caption Ingest ▼
                                                                              Google YouTube
```

## 2. What `pitube` Has (Capabilities & Endpoints)

`pitube` provides the complete YouTube live streaming lifecycle, stream health monitoring, ad-hoc broadcast creation, confidence preview embedding, and real-time live captions.

### A. Endpoints Provided by `pitube`

All endpoints are hosted at `http://pitube:3105` (and expected to be routed by `pigateway` under `/api/v1/youtube/*`):

#### 1. `GET /api/v1/status`
Returns full service status, active broadcast, ingestion health, caption statistics, and gateway connectivity.

* **Response (200 OK):**
```json
{
  "service": "pitube",
  "state": "ready",
  "selectedBroadcast": {
    "id": "dQw4w9WgXcQ",
    "title": "Jumalanpalvelus - Riihimäen Keskuskirkko",
    "description": "Suora lähetys",
    "scheduledStartTime": "2026-11-01T10:00:00.000Z",
    "actualStartTime": null,
    "privacy": "public",
    "status": "ready",
    "embedUrl": "https://www.youtube.com/embed/dQw4w9WgXcQ",
    "streamId": "stream_123"
  },
  "streamHealth": "good",
  "captions": {
    "sent": 142,
    "dropped": 2,
    "lastSentAt": 1761666010000,
    "lastError": null
  },
  "gateway": {
    "connected": true,
    "lastEventAt": 1761666005000,
    "epoch": "k3j2h1"
  }
}
```

#### 2. `GET /api/v1/broadcasts`
Queries YouTube Data API v3 for upcoming scheduled broadcasts on the channel.

* **Response (200 OK):**
```json
{
  "selectedId": "dQw4w9WgXcQ",
  "items": [
    {
      "id": "dQw4w9WgXcQ",
      "title": "Jumalanpalvelus - 1.11.2026",
      "scheduledStartTime": "2026-11-01T10:00:00.000Z",
      "privacy": "public",
      "status": "ready",
      "embedUrl": "https://www.youtube.com/embed/dQw4w9WgXcQ"
    },
    {
      "id": "kJQP7kiw5Fk",
      "title": "Pyhäinpäivän iltakirkko",
      "scheduledStartTime": "2026-11-01T18:00:00.000Z",
      "privacy": "public",
      "status": "ready",
      "embedUrl": "https://www.youtube.com/embed/kJQP7kiw5Fk"
    }
  ]
}
```

#### 3. `POST /api/v1/broadcasts/select`
Selects an upcoming broadcast to be the active streaming target, loads its bound RTMP stream key into memory, and prepares the caption sender.

* **Request Body:**
```json
{ "broadcastId": "dQw4w9WgXcQ" }
```
*(Or `{ "broadcastId": "auto" }` to let `pitube` select the closest scheduled broadcast within $\pm 60$ minutes).*
* **Response (200 OK):** Returns the selected `BroadcastSummary` object.

#### 4. `POST /api/v1/broadcasts/create`
Creates an ad-hoc live broadcast when no event was pre-scheduled in YouTube Studio, binds a reusable live stream, and immediately selects it.

* **Request Body:**
```json
{
  "title": "Jumalanpalvelus (Ad-hoc) - 1.11.2026",
  "privacy": "public",
  "description": "Suora lähetys Riihimäen Keskuskirkosta.",
  "scheduledStartTime": "2026-11-01T10:00:00.000Z"
}
```
* **Response (201 Created):** Returns the newly created and selected `BroadcastSummary`.

#### 5. `POST /api/v1/broadcasts/start`
Transitions the selected broadcast from `ready` / `testing` to **`live`**.
* Connects the live caption sender (`lcyt`) to YouTube's closed caption ingestion endpoint.
* Starts background health monitoring.
* Reports `{ state: "live" }` to `pigateway`.
* **Response (200 OK):** Updated `BroadcastSummary` with `status: "live"`.

#### 6. `POST /api/v1/broadcasts/stop`
Transitions the broadcast from `live` to **`complete`**.
* Halts live caption delivery.
* Releases the broadcast and resets state to `idle`.
* Reports `{ state: "offline" }` to `pigateway`.
* **Response (200 OK):** Completed `BroadcastSummary`.

#### 7. `GET /api/v1/broadcasts/current`
Convenience endpoint returning the current broadcast and its preview iframe URL:
* **Response (200 OK):**
```json
{
  "broadcast": {
    "id": "dQw4w9WgXcQ",
    "title": "Jumalanpalvelus - 1.11.2026",
    "privacy": "public",
    "status": "live",
    "embedUrl": "https://www.youtube.com/embed/dQw4w9WgXcQ"
  },
  "state": "live",
  "streamHealth": "good",
  "captions": {
    "sent": 84,
    "dropped": 0,
    "lastSentAt": 1761666010000,
    "lastError": null
  }
}
```

### B. YouTube Live Confidence Preview Support
* Every broadcast object provides `embedUrl`: `https://www.youtube.com/embed/{id}`.
* In `picontrol`, the iframe should be embedded with:
  ```html
  <iframe
    src="${broadcast.embedUrl}?autoplay=1&mute=1&enablejsapi=1"
    allow="accelerometer; autoplay; clipboard-write; encrypted-media; gyroscope; picture-in-picture"
    allowfullscreen>
  </iframe>
  ```
* All broadcasts created or selected by `pitube` have `enableEmbed: true` explicitly configured.
* Shows the stream as viewers see it at YouTube's ~30-second delay, including interactive closed caption verification (`[CC]`).

### C. Live Caption Delivery Engine
* Implements a fixed **30-second video delay offset** (`startedAt + 30000 ms`) per YouTube live captioning guidance.
* Drops stale captions (> 90 s) and only transmits while in `live` state.
* **Strict Secret Redaction:** RTMP stream keys and ingestion URLs never appear in any response, error message, or log.

## 3. What `pitube` Expects

### A. Gateway Routing & Authentication
1. **Network/Proxy Setup:**
   * `pigateway` routes requests matching `/api/v1/youtube/*` to `http://127.0.0.1:3105/api/v1/*`.
2. **API Key / Authorization:**
   * When `PITUBE_API_KEY` is configured in `pitube`, mutation requests (`POST /select`, `POST /create`, `POST /start`, `POST /stop`) must include:
     `Authorization: Bearer <PITUBE_API_KEY>` or `x-api-key: <PITUBE_API_KEY>`.
   * Read requests (`GET /status`, `GET /broadcasts`, `GET /broadcasts/current`, `GET /health`) are open.

### B. Operational Workflow & Preconditions Expected by `pitube`

```
 [ 1. Select / Create ] ──► [ 2. Encoder Starts ] ──► [ 3. Go Live ] ──► [ 4. End Stream ]
    (pick upcoming or          (Matrox HDX / ATEM        (POST /start;       (POST /stop;
      create ad-hoc)            pushes RTMP)             captions begin)      broadcast ends)
```

1. **Broadcast Selection Precondition:**
   * `POST /broadcasts/start` will fail with HTTP 400 if no broadcast has been selected or created.
   * `picontrol` should prompt the operator to confirm or pick a broadcast before enabling "Go Live".
2. **Hardware Video Encoder Precondition:**
   * `pitube` does not push video; it manages the YouTube API and captions.
   * The hardware encoder (Matrox Monarch HDX via `pigateway/api/v1/encoder` or ATEM) must start pushing RTMP to YouTube before (or immediately as) the broadcast transitions to `live`.
   * `picontrol` should display `streamHealth` (`good`, `ok`, `noData`). Going live while `streamHealth === "noData"` should show a warning to the operator.
3. **Permanent Completion on Stop:**
   * In YouTube Data API, transitioning a broadcast to `complete` is **irreversible**. A completed broadcast cannot be resumed or streamed to again.
   * `picontrol` must require explicit operator confirmation before firing `POST /broadcasts/stop`.
4. **Volume & Audio Hygiene:**
   * `picontrol` must embed the YouTube preview with `mute=1` to prevent acoustic feedback in the church audio booth.

## 4. State Machine Reference

| State | Ingest Health | Captions | Allowed Actions from picontrol |
| :--- | :--- | :--- | :--- |
| `idle` | `unknown` | Off | Select broadcast, Create ad-hoc broadcast |
| `ready` | `noData` $\rightarrow$ `good` | Off | Select different broadcast, Start broadcast (`POST /start`) |
| `testing` | `good` / `ok` | Off | Start broadcast (`POST /start`), Stop broadcast |
| `live` | `good` / `ok` | **Active (30s delay)** | Stop broadcast (`POST /stop`) |
| `complete` | `noData` | Off | Automatically returns to `idle` |
